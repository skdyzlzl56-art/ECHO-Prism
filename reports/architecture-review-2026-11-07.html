1. 장면(act) 수명주기를 한 module로

Strong in-process

game.js (pick) · battle.js (runBattle) · stage1/scenes.js (s1_explore, s1_party)

Before: 4 scenes, 4 copies of the same plumbing
flowchart TB
  P[pick] --> L1[class + canvas + raf + listeners + cleanup + done]
  B[runBattle] --> L2[class + canvas + raf + listeners + cleanup + done]
  E[s1_explore] --> L3[class + canvas + raf + listeners + cleanup + done]
  Y[s1_party] --> L4[class + canvas + raf + listeners + cleanup + done]
  classDef leak stroke:#dc2626,stroke-width:2px;
  class L1,L2,L3,L4 leak
After: scenes shrink to update + draw
runScene(mode, { update, draw, keys })
canvas / raf / dt
listeners add + remove
stage class toggle
done() exactly once
seam: each scene = one adapter (pick, battle, explore, party)

Problem: 수명주기 코드가 4번 복사되어 있고, 정리(cleanup)가 장면마다 다르게 틀릴 수 있다 (재도전은 cleanup 후 재귀 호출).

Solution: 장면은 update(dt)와 draw(g)만 내놓고, 수명주기는 module 하나가 맡는다.

  • locality: 누수·이중 종료 버그가 한 곳
  • leverage: 새 장면마다 20줄 감소
  • 4 adapters → 진짜 seam

2. 소리(sfx · bgm)를 한 module 뒤로

Strong local-substitutable

index.html (sweep, noise, blip, bgm, FX.sfx) · battle.js (shotSfx, 호출 20여 곳) · stage1/scenes.js · story.js

Before: 소리 값이 호출 지점마다 흩어짐
battle.js — sweep(1100, 450, .1, "triangle", .2)
scenes.js — sweep(520, 1040, .6, "sine", .16)
index.html FX — sweep(150, 600, 1.4, ...)
bgm VOL 표 — 0.3 → 0.2 (따로 조절)
After: 의미로 부르고, 값은 안에서
sound.play("enemyShot", { size, speed }) · sound.music("s1_boss")
oscillator 설계 · 위협도 → 길이/음량 · 볼륨 균형 · bgm 전환
adapters: WebAudio (prod) · silent (tests)

Problem: "소리가 묻힌다"는 조정이 두 번 나왔고, 매번 여러 파일을 고쳐야 했다.

Solution: 효과음을 이름과 의미(크기·속도)로 요청하고, 합성 값과 음량 균형은 module 안에 숨긴다.

  • locality: 음량 균형이 한 곳
  • leverage: 호출 20여 곳이 한 줄씩
  • silent adapter로 전투를 소리 없이 테스트

3. 전투 시뮬레이션을 화면·입력·소리에서 분리

Strong ports & adapters

battle.js (runBattle 약 250줄 클로저)

Before: 한 클로저에 전부
탄·광선·충돌·페이즈 (규칙)
canvas 그리기
키보드·마우스
소리 호출
대사 상자·DOM 정리
테스트하려면 브라우저를 띄워야 함
After: 규칙 module + 두 adapter
battle.step(dt, input) → { state, events }
phases · bullets · lasers · collision · ally · enemy movement · bond
canvas adapter → draw(state)
sound adapter ← events
headless test: 6페이즈를 돌려 "빈틈이 있는가" 검사

Problem: 전투 규칙이 canvas와 DOM에 묶여 있어서, 패턴 검증을 하려면 브라우저에서 억지로 돌려야 했다. 동료·적 이동 같은 새 규칙도 이 한 클로저에 계속 쌓인다.

Solution: 규칙을 step(dt, input) 뒤에 두고, 그리기와 소리는 상태와 이벤트를 받는 adapter로 만든다.

  • interface가 test surface가 됨
  • locality: 판정 버그가 한 module
  • 2 adapters (canvas, headless) → 진짜 seam

4. 대사 진행(dialogue)을 module로: Ctrl 스킵이 내부를 엿봄

Worth exploring in-process

index.html (next, advance, show, tick, finish, bgm 트리거, Ctrl 스킵) · script.js · stage1/story.js (SCRIPT.push)

Before: 전역 상태 + 외부 접근
flowchart LR
  CK[Ctrl 스킵 setInterval] -. reads .-> S{{idx · busy · acting · timer}}
  AD[advance] --> S
  NX[next] --> S
  ST[stage1/story.js] -. SCRIPT.push .-> SC[SCRIPT]
  classDef leak stroke:#dc2626,stroke-width:2px;
  class CK,ST leak
After: 작은 interface
dialogue.advance() · dialogue.skip(on)
타이핑 · 효과 대기 · 장면 위임 · bgm 신호 · 스크립트 끝
seam: 스크립트는 데이터로 등록 (stage = 데이터 module)

Problem: 스킵 기능이 busy·acting 같은 내부 상태를 직접 읽고, 스테이지는 로드 순서에 기대어 SCRIPT에 끼어든다.

Solution: 진행 상태를 module 안에 숨기고, 입력은 advance와 skip만 쓴다.

  • locality: 스킵 버그가 한 곳
  • 스테이지 2 추가가 파일 하나

5. 캐릭터 외형 한 곳에서 (루미·헥사가 세 번 그려짐)

Worth exploring in-process

portraits.js (bloom, rings, fairy) · battle.js (동료 꽃잎 인라인) · stage1/scenes.js (drawBlossom, drawHexa, drawFairy)

Before: 같은 모양, 세 곳
portraits.js · bloom()
battle.js · 꽃잎 for-loop (인라인 복사)
scenes.js · drawBlossom()
After: 외형 = SPEAKERS 데이터 하나
drawLook(g, speakerKey, x, y, t, scale)
bloom · rings · fairy · shard · orb 전부
초상화 · 전투 동료 · 탐색 · 카드가 같은 interface 사용

Problem: 루미의 외형을 바꾸려면 세 파일을 고쳐야 한다. 이미 어긋나기 시작했다 (크기·색 처리가 다름).

Solution: 화자 키와 크기로 그리는 module 하나로 모은다.

  • locality: 외형 수정이 한 곳
  • delete 3 near-duplicates
Top recommendation

3. 전투 시뮬레이션 분리

변경이 가장 잦은 module이고(커밋마다 수정, 오늘도 동료 유대·적 이동 요청이 같은 클로저로 들어감), 테스트가 하나도 없는 이유가 곧 이 module의 모양이다. seam을 세우면 패턴 검증이 가능해지고, 2번(소리)과 1번(장면)이 그 위에서 자연스럽게 따라온다.
