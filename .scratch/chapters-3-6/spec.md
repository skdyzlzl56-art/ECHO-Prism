# 챕터 3~6 (미술관 · 시계탑 · 도서관 · 프리즘 코어)

## Problem Statement

플레이어는 에코 프리즘의 스테이지 1(등불의 회랑)과 스테이지 2(소리 없는 정원)를 끝냈지만, 침묵과의 싸움은 "지금은 이길 수 없다"로 끝나 있다. 이야기는 열린 채 멈췄고, 유대·교대 같은 시스템도 스테이지 2 이후 쓸 곳이 없다. 플레이어는 이야기를 끝까지 보고 싶다.

## Solution

스테이지 3~6을 추가해 이야기를 완결한다. 각 챕터는 새 무대, 새 보스 규칙, 스테이지 2의 약 3배 분량(약 150줄)의 대사, 전용 BGM 2곡(필드·보스)을 가진다. 챕터 3·4에서 동료가 한 명씩 늘어 총 4명이 되고, 챕터 6에서 침묵과 결전해 이긴 뒤 ???의 정체와 개체의 이름이 밝혀지고 타이틀로 돌아간다.

## User Stories

1. 플레이어로서, 스테이지 2 탈출 직후 자연스럽게 스테이지 3으로 이어지길 원한다. 그래야 이야기가 끊기지 않는다.
2. 플레이어로서, 각 챕터가 뚜렷한 무대와 주제(색·시간·이름·코어)를 갖길 원한다. 그래야 챕터를 구분해 기억한다.
3. 플레이어로서, 챕터 3(색을 잃은 미술관)에서 화면의 색 영역이 지워지는 보스를 만나고 싶다. 그래야 같은 색의 탄만 맞는 새 규칙을 배운다.
4. 플레이어로서, 챕터 3에서 첫 새 동료를 얻고 싶다. 그래야 교대할 선택지가 늘어난다.
5. 플레이어로서, 챕터 4(멈춘 시계탑)에서 탄이 되감기는 보스를 만나고 싶다. 그래야 궤적을 예측하는 새 재미가 생긴다.
6. 플레이어로서, 챕터 4에서 두 번째 새 동료를 얻고 싶다. 그래야 총 4명이 모인다.
7. 플레이어로서, 챕터 5(이름 없는 도서관)에서 이름이 적힌 탄을 피하는 보스를 만나고 싶다. 그래야 방향을 읽는 규칙을 배운다.
8. 플레이어로서, 챕터 5에서 개체의 과거 단서를 얻고 싶다. 그래야 최종장의 반전이 설득력을 갖는다.
9. 플레이어로서, 챕터 6에서 앞의 세 규칙이 페이즈마다 섞여 나오는 최종 보스를 만나고 싶다. 그래야 배운 것의 총결산이 된다.
10. 플레이어로서, 4명의 동료를 X키로 순환 교대하고 싶다. 그래야 상황에 맞춰 동료를 바꾼다.
11. 플레이어로서, 교대해도 유대 레벨(상한 4)이 하나의 값으로 이어지길 원한다. 그래야 교대가 손해가 되지 않는다.
12. 플레이어로서, 동료마다 서로 다른 유대의 빛 효과를 보고 싶다. 그래야 동료마다 쓰는 맛이 다르다.
13. 플레이어로서, 챕터 6에서 4명이 함께 터지는 합동 유대의 빛을 보고 싶다. 그래야 여정의 정점이 느껴진다.
14. 플레이어로서, 새 동료가 기존 보스나 균열이 해방되는 방식으로 합류하길 원한다. 그래야 헥사와 같은 구원 서사가 이어진다.
15. 플레이어로서, 침묵이 소멸하지 않고 "잊힌 기억의 외로움"으로 구제되길 원한다. 그래야 글리치·헥사와 이어지는 주제가 완성된다.
16. 플레이어로서, ???의 정체(세계 자체의 의식)가 밝혀지길 원한다. 그래야 처음부터 깔린 비밀이 풀린다.
17. 플레이어로서, 개체가 마지막 한 줄만 처음으로 말하길 원한다. 그래야 침묵하던 주인공의 마지막이 감동적이다.
18. 플레이어로서, 개체에게 고정된 이름이 주어지길 원한다. 그래야 이야기가 결말을 맺는다.
19. 플레이어로서, 엔딩 후 타이틀로 돌아가길 원한다. 그래야 다시 시작할 수 있다.
20. 플레이어로서, 챕터마다 필드곡과 보스곡이 따로 있길 원한다. 그래야 분위기가 전환된다.
21. 플레이어로서, 챕터 6의 곡이 앞 곡들의 모티프를 다시 쓰길 원한다. 그래야 음악으로도 결말이 느껴진다.
22. 플레이어로서, 챕터마다 잡몹 전투 → 보스전 → 이벤트(도주·해방 등) 흐름이 있길 원한다. 그래야 리듬이 일정하다.
23. 플레이어로서, 챕터 3에는 스테이지 1 같은 탐색 장면이 있길 원한다. 그래야 전투만 반복되지 않는다.
24. 플레이어로서, 보스전 중 페이즈마다 동료·적의 대사가 끼어들길 원한다. 그래야 전투도 이야기가 된다.
25. 개발자로서, 새 보스 규칙이 헤드리스 테스트로 검증되길 원한다. 그래야 자리를 비운 사이 자율 실행이 회귀 없이 진행된다.
26. 개발자로서, 챕터마다 커밋이 나뉘길 원한다. 그래야 문제 챕터만 되돌린다.
27. 개발자로서, 새 용어가 GLOSSARY.md와 CHARACTERS.md에 기록되길 원한다. 그래야 이후 작업이 같은 말을 쓴다.

## Implementation Decisions

- **챕터 골격**: 스테이지 1·2와 같은 구성. 챕터마다 대사 스크립트(약 150줄), 전투 설정 묶음(2~3개), 필요 시 탐색 장면을 가진 독립 폴더. 스크립트는 이전 챕터 뒤에 이어 붙는 기존 방식을 따른다.
- **무대/보스 규칙(전투 규칙 모듈의 옵션으로 추가)**:
  - 3 미술관: 색 영역이 지워지고 같은 색의 탄만 피격 판정(색 규칙).
  - 4 시계탑: 일정 주기(약 5초)마다 탄이 되감기며 궤적이 반복(되감기 규칙).
  - 5 도서관: 이름 탄은 같은 방향으로 이동하면 안전(방향 규칙).
  - 6 코어: 세 규칙을 페이즈마다 하나씩 섞고, 침묵과의 결전은 마지막 페이즈에서 합동 유대의 빛으로 끝난다.
- **전투 규칙은 기존 옵션 방식 유지**: 새 규칙은 전투 설정의 옵션 필드로 켜고 끄며, 옵션이 없는 기존 전투(스테이지 1·2)의 동작은 바뀌지 않는다.
- **동료**: 챕터 3에서 1명, 챕터 4에서 1명 추가해 총 4명(루미, 헥사 + 2). 모두 기존 보스·균열이 해방되어 합류한다. X키는 4명을 순환 교대, 쿨타임은 기존 값 유지. 새 동료 형태는 `CHARACTERS.md`의 "형태 = 성격" 원칙에 따라 도형 방식으로 추가한다.
- **유대**: 상한 Lv.4 유지, 하나의 값 공유. 동료마다 유대의 빛 효과를 하나씩 정한다(루미 = 회복, 헥사 = 방패 등 기존 역할을 유지하고 새 2명은 서로 다른 역할). 챕터 6에서 4명 합동 유대의 빛 연출.
- **스토리**: 침묵은 소멸하지 않고 개체의 첫 기억으로 돌아간다. ???는 세계 자체의 의식으로 밝혀지고 개체에게 이름을 준다(고정 이름 한 가지, 예: "에코"). 개체는 마지막 한 줄만 말한다. 엔딩 후 타이틀로 복귀. 챕터 5에서 개체 과거 단서를 깐다.
- **음악**: 챕터당 2곡. 3 = 재즈 피아노(필드)/거친 현악 록(보스), 4 = 째깍이는 미니멀 현악/변박 일렉, 5 = 느린 첼로+하프/합창풍 신스 오케스트라, 6 = 앞 모티프 재등장/스테이지 1 보스곡 조성 마무리. 곡 전환은 스크립트 줄의 `bgm` 키를 따른다.
- **용어**: 새 개념(색 규칙, 되감기 규칙, 방향 규칙, 합동 유대의 빛, 무대 이름 4개)은 GLOSSARY.md에 추가하고 이 문서의 이름을 그대로 쓴다.

## Testing Decisions

- **좋은 테스트의 기준**: 전투 규칙의 외부 동작만 확인한다(예: 같은 색 탄에만 피해가 들어가는가, 되감기 뒤 탄 위치가 재현되는가). 내부 자료 구조는 보지 않는다.
- **테스트 대상 seam은 하나**: 헤드리스 전투 시뮬레이션(`createBattle` + `step`)에 설정 객체를 넣어 이벤트를 검증한다. 대사·연출·음악은 이 seam 밖이며 직접 플레이로 확인한다.
- **선례**: 기존 `sim.test.js`의 시드 고정 난수, `run` 헬퍼, `quiet` 설정 패턴. `node --test webgame/battle`로 실행.
- 새 규칙마다 최소 한 개의 테스트, 기존 테스트 전체가 계속 통과해야 한다. 스크립트 데이터의 구조 오류(없는 BGM 키, 없는 화자)는 챕터 로드 시 즉시 드러나도록 한다.

## Out of Scope

- Godot 포팅(웹과 이미 어긋나 있음).
- 도형 색 선택, 맵 탐사 확장(챕터 3 탐색 1개 제외).
- 5명 이상의 동료, 유대 상한 변경.
- 모바일 입력, 세이브 시스템, 난이도 선택.
- 음악의 품질 보증(자동 생성까지만, 청취 판단은 사용자).

## Further Notes

- 대사량은 챕터당 약 150줄(스테이지 2의 약 46줄의 3배)을 기준으로 한다.
- 자율 실행 시 챕터마다 커밋하고, 직접 플레이 확인은 마지막에 한 번 한다.
- 시작 전에 현재 작업 트리의 미커밋 변경(스테이지 2 음악 등)을 먼저 커밋해 통합 브랜치와 섞이지 않게 한다.
